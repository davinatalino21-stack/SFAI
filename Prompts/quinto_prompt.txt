# Prompt Completo — Correções de Bugs, Responsividade e Melhorias de Interface

Realize uma revisão completa da interface da aplicação **SF AI**, com foco em **correção de bugs, responsividade, usabilidade, organização visual, consistência da interface e limpeza do código**.

Implemente todas as correções descritas abaixo **sem alterar desnecessariamente a identidade visual ou o funcionamento atual da aplicação**.

---

# 1. Corrigir responsividade dos botões da Home no Mobile

## Problema

Na versão mobile da Home, os botões **“Acessar o ChatBot”** e **“Começar conversa”** estão ultrapassando parcialmente os limites da tela, ficando cortados ou fora da área visível.

## Objetivo

Corrigir o layout responsivo para que os botões fiquem completamente dentro da tela em dispositivos móveis.

### Requisitos

* Os botões devem respeitar a largura disponível da tela.
* Não deve existir overflow horizontal.
* Os botões devem ficar completamente visíveis.
* Manter o visual atual dos botões:

  * Gradiente.
  * Cores.
  * Tipografia.
  * Border-radius.
  * Estilo geral.
* O ajuste deve funcionar em diferentes tamanhos de celulares.
* Não fazer uma correção específica apenas para uma resolução.
* Não alterar desnecessariamente a versão desktop.

---

# 2. Não alterar o layout do chatbot ao iniciar uma conversa

## Problema

Ao iniciar uma conversa, a interface do chatbot pode alterar sua estrutura, tamanho ou posicionamento dos elementos.

## Objetivo

Ao iniciar uma conversa, **o layout deve permanecer no mesmo padrão visual e estrutural existente**.

### Requisitos

Manter:

* Barra lateral na mesma posição.
* Área principal do chatbot.
* Campo de mensagem.
* Botão **“Enviar”**.
* Espaçamentos.
* Proporções.
* Estrutura geral da interface.

A conversa deve simplesmente ser iniciada dentro do layout existente.

### IMPORTANTE

Não criar um novo layout quando uma conversa for iniciada.

A correção da responsividade mobile também não deve causar alterações indesejadas no layout do chatbot.

* Manter o funcionamento dos demais componentes.

* Não alterar desnecessariamente a versão mobile.

# 4. Corrigir elemento “12 DIREC” aparecendo sobre o campo de mensagem

## Problema

Na versão mobile, um elemento/trecho de conteúdo aparece indevidamente atrás/acima do campo de mensagem. Na imagem de referência, é possível visualizar parcialmente o texto **“12 DIREC”**.

Esse conteúdo está sobreposto à interface e não deveria aparecer nessa região.

## Objetivo

Eliminar completamente esse problema de sobreposição.

### Requisitos

* Identificar a origem do elemento “12 DIREC”.
* Corrigir o posicionamento/overflow responsável pelo problema.
* Impedir que conteúdos da conversa apareçam atrás do campo de mensagem.
* Impedir sobreposição entre mensagens/conteúdo e a área de entrada.
* Garantir que o campo de mensagem fique totalmente visível.
* Garantir que o botão “+” do campo de mensagem continue funcionando.
* Garantir que o botão de envio continue visível e funcionando.
* A correção deve funcionar em diferentes tamanhos de dispositivos móveis.

# 5. Adicionar botão de voltar em todas as abas — Mobile

Isso dificulta a navegação.

## Objetivo

Adicionar um botão de voltar ou fechar em **todas as abas/painéis da aplicação no mobile**.

### Requisitos

* Adicionar o botão em todos os painéis laterais.
* Posicioná-lo no cabeçalho da respectiva aba.
* O botão deve fechar somente a aba/painel atual.
* Não deve encerrar a conversa.
* Não deve alterar outras abas.
* Manter o padrão visual existente.
* Utilizar uma seta para a esquerda ou ícone de fechar apropriado.
* Garantir funcionamento em diferentes dispositivos móveis.

# 9. Padronizar os botões principais da Home

### Se ambos permanecerem

Eles devem possuir:

* Mesmo tamanho.
* Mesma altura.
* Mesma largura ou comportamento responsivo equivalente.
* Mesmo gradiente.
* Mesma tipografia.
* Mesmo padding.
* Mesmo border-radius.
* Mesmo efeito hover.
* Mesmo efeito de clique.
* Mesmo padrão de alinhamento.

### Se executarem exatamente a mesma função

Manter apenas um dos botões e remover o redundante.

### IMPORTANTE

Essa alteração não deve prejudicar a correção de responsividade descrita no **Bug 1**.

# 11. Análise da causa raiz

Antes de implementar cada correção, **identifique brevemente a causa raiz do problema**.

Não aplicar simplesmente alterações aleatórias de CSS.

Verificar se o problema é causado por:

* `overflow`;
* largura fixa;
* `min-width`;
* `max-width`;
* `height`;
* `position`;
* `z-index`;
* `flex`;
* `grid`;
* margens;
* padding;
* containers;
* breakpoints;
* elementos duplicados;
* estados da aplicação;
* rotas;
* componentes;
* ou qualquer outra causa relacionada.

Depois, implemente a solução mais adequada.
